# Política De Contexto Y Continuidad

## Inicio

1. Leer `AGENTS.md` y `docs/ai/PROJECT_CONTEXT.md`.
2. Leer el pedido o artefacto activo.
3. Leer `CONTINUITY.md` cuando exista y la tarea continúe trabajo previo.
4. Consultar `ACTIVATION_MATRIX.md` si la skill no es evidente.
5. Activar una skill principal por fase.
6. Leer sólo policies, documentos técnicos y código afectados.

## Puntos De Verdad

- `PROJECT_CONTEXT.md`: dominio, stack y restricciones.
- `DECISIONS.md`: decisiones con tradeoff.
- `docs/technical/`: contratos vivos.
- `docs/backlog/`: trabajo durable.
- `docs/changes/`: solicitudes formales.
- `CONTINUITY.md`: handoff breve.
- `SOFTWARE_FACTORY.md`: proceso del kit.

## Reglas

- No cargar el manifest, archivos históricos o todo el backlog sin una razón.
- No crear un punto de verdad alternativo si uno existente cubre la necesidad.
- Nivel 0/1 no crea backlog ni documentos por defecto.
- Mantener `CONTINUITY.md` factual, corto y sin secretos.
